# LLM baselines, 2026-11-02 (step 0 of docs/llm-design.md)

Reference speeds that in-container WebGPU inference will be compared with.
Nothing here is our inference code. Machine: Apple M4 Max (16 cores), macOS
27.2, 8 interleaved rounds per configuration, the first dropped as warm-up
(cold browser and page cache), so **n = 7**. Every run started with a 1-minute
load average of at most 8 (the harness waits otherwise; it waited 14 checks
once, when other sessions pushed the load above 80). Round-by-round loads are
in `data/results-2026-11-02.json` (`load1`, taken just before the run).

## Results (tokens per second, p50 and min-max over 7 rounds)

pp = 128 prompt tokens, tg = 128 generated tokens (every WebLLM run reported
`prompt_tokens` 128 and `completion_tokens` 128; `ignore_eos`, temperature 0).

| Configuration | prefill p50 | prefill min-max | decode p50 | decode min-max |
|---|---|---|---|---|
| SmolLM2-135M llama.cpp Q4_0, CPU, `-t 1` | 1145.4 | 1102.5 - 1146.2 | 467.3 | 463.8 - 470.0 |
| Qwen2.5-0.5B llama.cpp Q4_0, CPU, `-t 1` | 401.0 | 391.5 - 405.2 | 142.0 | 140.3 - 142.9 |
| SmolLM2-135M WebLLM q4f16_1, Chrome, Apple GPU | 2831.9 | 2717.6 - 3152.7 | 226.9 | 191.7 - 228.5 |
| SmolLM2-135M WebLLM q4f32_1, Chrome, Apple GPU | 2655.6 | 2456.8 - 2857.1 | 223.6 | 167.0 - 227.8 |
| Qwen2.5-0.5B WebLLM q4f16_1, Chrome, Apple GPU | 2475.8 | 2173.2 - 2746.8 | 184.4 | 180.9 - 185.0 |
| Qwen2.5-0.5B WebLLM q4f32_1, Chrome, Apple GPU | 2184.3 | 2140.5 - 2452.1 | 177.0 | 175.6 - 177.5 |
| SmolLM2-135M llama.cpp Q4_0 Metal (context only) | 18485.5 | 17981.6 - 19238.6 | 549.7 | 508.1 - 562.7 |
| Qwen2.5-0.5B llama.cpp Q4_0 Metal (context only) | 10307.5 | 10125.3 - 10551.6 | 435.4 | 429.7 - 460.6 |

Reading it: at one core, llama.cpp decodes 142 tok/s (Qwen) and 467 tok/s
(SmolLM2); WebLLM on the GPU decodes 177-184 and 224-227. The targets of
llm-design.md follow: our CPU path must reach the first two rows; browser
decode is compared with the WebLLM rows (q4f16_1 where `shader-f16` exists,
q4f32_1 for the f32 path). Formats differ (ggml Q4_0 blocks against MLC
group quantisation q4f16_1 / q4f32_1); the rows say which.

Caveats. Browser prefill is WebLLM's own `prefill_tokens_per_s` for one 128-token chunk
(`cs1k` libraries); on these small models it is tens of milliseconds, so its
spread is wider than decode's. Metal rows ran with `-t 1`. The first round
(dropped) showed cold-start prefill figures of 470-540 tok/s for three of the
four WebLLM rows, which is why it is not counted.

SmolLM2-135M has no q4 entry in WebLLM 0.2.87's prebuilt list (only q0f16 and
q0f32); its q4f16_1 and q4f32_1 MLC builds and libraries exist upstream and are
run through a custom `appConfig`, with the same library version as the others.
The wasm and weights are served from the pinned local files, so the network
plays no part and the pins are exact. The SmolLM2 GGUF comes from bartowski,
as HuggingFaceTB publishes no GGUF repository for the 135M Instruct model.

## Commands

Harness: `internal/cmd/llmbaseline` (Go, cobra, tests in the same directory).
Corpus in `~/Documents/VCS/GIT/localhost/go-wasmcontainers-llm-corpus/`.

```
llmbaseline hf --dir . Qwen/Qwen2.5-0.5B-Instruct-GGUF qwen2.5-0.5b-instruct-q4_0.gguf
llmbaseline hf --dir . bartowski/SmolLM2-135M-Instruct-GGUF SmolLM2-135M-Instruct-Q4_0.gguf
llmbaseline hf --dir . mlc-ai/<each of the four MLC repositories>
llmbaseline url --out libs/<name>.wasm https://raw.githubusercontent.com/mlc-ai/binary-mlc-llm-libs/146ed9cd.../web-llm-models/v0_2_87/base/<name>.wasm
llmbaseline run --corpus . --bench-cpu llama.cpp-v0.8.0/build-cpu/bin/llama-bench \
  --bench-metal llama.cpp-v0.8.0/build/bin/llama-bench \
  --smollm2 bartowski/SmolLM2-135M-Instruct-GGUF/SmolLM2-135M-Instruct-Q4_0.gguf \
  --qwen Qwen/Qwen2.5-0.5B-Instruct-GGUF/qwen2.5-0.5b-instruct-q4_0.gguf \
  --out results-2026-11-02.json --rounds 8
llmbaseline table results-2026-11-02.json          # drops round 1
```

Each llama.cpp run is `llama-bench -m FILE -t 1 -ngl 0 -p 128 -n 128 -r 1 -o json`
(`-ngl 99` for Metal), which includes llama-bench's own warm-up. Each WebLLM run
launches a fresh Chrome for Testing, opens a local page, creates the engine,
generates 8 warm-up tokens, calls `resetChat`, then generates 128 tokens from a
128-token prompt ("the" repeated, one token each in both tokenizers) and
reads `usage.extra.prefill_tokens_per_s` and `decode_tokens_per_s`. Within a
round every configuration runs once, the starting one rotating from round to
round; the load is read from `uptime` before each run.

Raw samples: `data/results-2026-11-02.json`; table: `data/table.md`; pins:
`data/pins-*.json`.

## Not measured

Firefox (WebLLM needs its own f32 path there; the q4f32_1 rows are the proxy),
`-ngl 99` with more than one thread, long contexts, allocation counts.
